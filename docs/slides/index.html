문제

이종 로봇 팀의 coalition 스케줄링

Paper Figure 1. (a) 여러 skill 조합이 필요한 task, 전원이 도착해야 시작 → 먼저 온 로봇은 대기 (b) ALNS (c) compute-matched 프로토콜

왜 어려운가

동기화: 마지막 멤버가 도착해야 시작

  • task는 skill 벡터 요구량 $r_j$ → 한 로봇으로 불가, coalition 필요
  • 시작 시각 = 멤버 도착의 max → 늦은 한 명이 모든 downstream task 지연
  • 공유 task 순서가 엇갈리면 deadlock: A는 $j\to k$, B는 $k \to j$
  • Gerkey 분류상 ST-MR-TA: coalition 형성 + routing + scheduling 한 문제
정식화 · Dai et al. 2025 그대로

문제 정의

agent $i\in A$: trait $a_i\in\{0,1\}^K$, depot $o_i$, 속도 $v$
task $j\in T$: 위치 $x_j$, 소요 $d_j$, 요구 $r_j\in\mathbb N^K$

이동시간 (Euclidean) $$\tau_{jk}=\frac{\lVert x_j-x_k\rVert}{v}$$

coverage: $\displaystyle\sum_{i\in C_j} a_i \;\ge\; r_j$ (성분별)
start: $\displaystyle s_j=\max_{i\in C_j}\alpha_{ij},\qquad f_j=s_j+d_j$
travel: $\alpha_{ik}=f_j+\tau_{jk}$ ($i$의 다음 task가 $k$)
목표: $\min\; M=\max_i\,(\text{depot 귀환 시각})$ — makespan

벤치마크: SA-BT (단일 skill, binary) · SA-AT (additive, 최대 2) · MA-AT (다중 skill). 시뮬레이터 limit 200 초과 = 실패 (makespan 200으로 계산)

Deadlock-free

모든 route 선행관계가 $\pi$를 따름 → cycle 불가

Exact

시뮬레이터와 동일한 이동시간 → makespan 재현 (수백 plan 테스트)

Minimal cover

시뮬레이터는 이미 cover된 task에 합류 불가 → 불필요 멤버 없음 유지

방법 ① 이 제한으로 잃는 것 없음

Proposition

모든 deadlock-free 계획에 대해, makespan이 더 크지 않은 minimal-cover 계획 $(\pi,C)$가 존재한다.

  1. $\pi$ = 시작시각 순 정렬 (동률은 route 선행관계 topological order) → 같은 스케줄
  2. 중복 멤버 $i$를 하나씩 제거: task $j$는 더 적은 도착의 max → 늦어지지 않음
  3. 제거된 $i$는 이전 위치 $p$에서 다음 task $k$로 직행. triangle inequality:
    $$f_j+\tau_{jk}\;\ge\;\alpha_{ij}+\tau_{jk}\;=\;f_p+\tau_{pj}+\tau_{jk}\;\ge\;f_p+\tau_{pk}$$
  4. 시작시각은 도착에 대해 monotone → 어떤 task도, 어떤 귀환도 늦어지지 않음 ∎

방법 ② 선형시간 정확 평가

tail $\theta$로 $O(|C_j|)$ 평가

tail $\theta_k$ = task $k$ 시작부터 끝까지 최장경로 (route DAG의 longest path)

$$\theta_k = d_k + \max_{i\in C_k}\big(\tau_{k,\,\text{next}_i(k)}+\theta_{\text{next}_i(k)}\ \text{or}\ \tau^{\text{home}}_{ik}\big)$$
$$M'=\max\Big(M,\; s_j+d_j+\max_{i\in C_j}\big(\tau_{j k_i}+\theta_{k_i}\big)\Big)$$
  • arc $p\to k$ 를 $p\to j\to k$ 로 교체 → triangle inequality로 절대 짧아지지 않음 ⇒ 근사 아닌 정확값
  • 한 번의 sweep으로 모든 위치 점수화 · 64개 초과 시 64개 후보만 (처음·끝·$j$ 근접)
  • 탐색 목적 $g = M + \lambda\cdot\overline{f}$ ($\lambda=0.1$): makespan 동률 깨기 + slack 보상

해석

왜 탐색이 이기나

RL

한 번의 순차 결정으로 plan 구성. rollout을 늘리면 다양성은 늘지만 주어진 plan을 개선하지 않음

ALNS

같은 시간에 plan 하나를 싸고 정확한 move 수천 번으로 개선. 모든 move feasible + $O(|C_j|)$ 평가

CP-SAT

step당 이웃은 더 풍부하지만 매 step 모델 빌드·풀이 비용 → 병렬화 효과 미미

메시지: 학습이 틀렸다는 게 아님 — learned planner는 같은 compute의 강한 탐색과 비교돼야 한다.

Negative result

Track D: 동적 / 열화 네트워크

DynHeteroMRTA-X 환경 + SPARC planner + T2 통신 계층을 1주 구축, dev에서 go/no-go gate 사전 설정

  • K0 통과: executor ↔ env bit-for-bit 일치
  • K1 발동: SPARC-L / rolling constructor = 0.9847 [0.981, 0.989] → 1.5%만 우위
  • K6 발동: 분할 네트워크에선 INF-r이 가장 robust

결론

동적 방법 주장(C1-dyn) 철회 → supplement의 negative result. 논문 한계에 명시: “정적·중앙 계획만 평가, RL의 분산·반응성 장점은 미평가”
