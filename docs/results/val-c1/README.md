# Stronger baselines and the same-host C1/C2 dry run on val (2026-09-28)

Written up in `docs/baselines-2026-09.md`. Regenerated by `analyze.sh` from runs/tune_dev, runs/bks, runs/anytime and
runs/anytime_c1 (gitignored; the raw rows are in the run archive named in `docs/HANDOFF.md`).

- `tune_dev.txt`: dev tuning of the new CP-SAT competitors (`anytime.py tune-report`): per setting, each PCPSAT
  sub-solve time and CPFULL arc restriction, with ALNS2 and CPSAT as references, 8 cores at B1.
- `bks_val.txt`, `bks_val.csv`, `bks_val_runs.csv`, `bks_val_plans.json.gz`: best known plan per val instance over
  every run so far (both hosts, the long BKS runs and the independent references), the best ALNS-derived plan and the
  best plan without any ALNS component, certified CP-SAT bounds; plans with 0-based routes (`routes_base` 0).
- `c1_val.txt`, `c1_val.md`, `anytime_gaps_val.csv`, `anytime_ratios_val.csv`, `c1_val.png`: the grid-c1 campaign
  (`anytime.py report --grid c1`): mean gap to the best known plan per method, cores and budget; CPU used per method;
  paired ratios ALNS2 / competitor with bootstrap CIs, wins-losses and Holm-corrected one-sided t-tests; the anytime
  curves (val 0-4); at the end of `c1_val.txt`, the cells the first host's Phase 1b campaign also ran.
- `c1_val_all.txt`, `c1_val_all.md`: the same keeping disturbed rows (there were none).
